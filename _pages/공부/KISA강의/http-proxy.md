# HTTP 응답 코드 & 프록시(Burp Suite) 

## HTTP 응답 코드(Status Code)
- 클라이언트 요청이 서버에서 어떻게 처리됐는지 보여주는 정보임
- 200번대: 요청 성공 (예: 200 OK)
- 300번대: 리다이렉션(Redirection), 추가 동작이 필요함 (예: 302 Found - 요청한 리소스가 다른 위치에 있어 그쪽으로 리다이렉트됨)
- 400번대: 클라이언트 요청에 문제가 있음
  - 400 Bad Request: 요청 형식 오류
  - 401 Unauthorized: 인증이 필요함
  - 403 Forbidden: 접근 권한이 없음
  - 404 Not Found: 요청한 리소스가 없음
- 500번대: 서버에서 요청 처리 중 문제 발생
  - 500 Internal Server Error: 서버 내부에서 알 수 없는 오류 발생
  - 503 Service Unavailable: 서버가 일시적으로 요청을 처리할 수 없음

## 버그헌팅 관점의 응답 코드 활용
- 예상치 못한 응답 코드가 나오면 서버가 예상과 다른 방식으로 요청을 처리하고 있다는 신호임
  - 예: 인증이 필요 없는 요청에서 401이 뜬다면 인증 메커니즘(Authentication Mechanism) 자체에 문제가 있을 가능성이 있음
- 404 페이지도 활용 가치가 있음
  - 오타/잘못된 경로 요청 시 뜨는 404를 통해 서버의 URL 구조를 유추할 수 있음
  - 일관된 URL 패턴(예: `/user/1`, `/user/2`)을 파악하면 테스트되지 않은 새로운 경로를 예측해볼 수 있음
  - 404 에러 페이지 자체가 민감 정보를 노출하거나 예기치 않은 동작을 유발할 수도 있어서 페이지 내용도 확인해볼 필요가 있음

## 일반적인 클라이언트-서버 통신 흐름
- 클라이언트(보통 브라우저)가 URL, HTTP 메서드, 헤더, 쿠키, (필요시) 요청 본문(Request Body)을 담아 요청을 보냄
- 서버가 요청을 분석하고 적절한 작업을 수행함
- 서버가 상태 코드, 응답 헤더, 쿠키, 응답 본문(HTML/JSON 등)을 담아 응답을 반환함

## 프록시(Proxy)를 거친 통신 흐름
- 프록시는 클라이언트와 서버 사이에 위치해 모든 HTTP 트래픽을 중개함
- 클라이언트 → 프록시 → 서버 순으로 요청이 전달됨 (프록시가 요청을 수정/로깅/차단할 수 있음)
- 서버 → 프록시 → 클라이언트 순으로 응답이 전달됨 (프록시가 응답을 수정/로깅할 수 있음)
- 장점: 보안 강화, 성능 향상, 로깅 및 디버깅(Debugging) 등
- 버그헌팅에서는 프록시 도구로 요청/응답을 자세히 분석하고, 요청을 수정해서 재전송하며 애플리케이션 동작을 파악하는 데 활용함

## Burp Suite 주요 기능
- Proxy: 클라이언트-서버 간 HTTP 통신을 캡처(Capture)하고 분석함. 필요하면 요청/응답을 직접 수정 가능
- Repeater: 캡처한 요청을 재사용/수정해서 반복 전송함. 같은 요청을 값만 바꿔가며 여러 번 테스트할 때 유용함
- Intruder: 지정한 위치의 값을 자동으로 바꿔가며 요청을 반복 전송함. 입력값에 따른 서버 반응을 빠르게 테스트할 때 유용함
- Burp Suite Pro: 자동 스캔(Automated Scan)으로 취약점을 자동 탐색하거나, 확장 프로그램(Extension)으로 맞춤형 테스트를 수행할 수 있음

## 실습 흐름 메모
1. Burp Suite 실행 → Proxy 탭에서 Open Browser 클릭 (내장 브라우저라 별도 프록시 설정 없이 패킷 캡처 가능)
2. Intercept 옵션을 켠 상태에서 검색 등 요청을 보내면 Request 패킷이 잡힘
3. Response까지 잡으려면 Proxy 설정에서 Response 캡처 옵션을 켜야 함
4. 잡힌 패킷 우클릭 → Send to Repeater로 보내면 Repeater 탭에서 값을 바꿔가며 재전송 가능
5. Repeater 또는 Proxy에서 우클릭 → Send to Intruder로 패킷 전송
6. Attack Type 설정 (예: Sniper) → 테스트할 파라미터 위치를 드래그 후 Add로 지정
7. Payloads 탭에서 넣고 싶은 값(예: `123`, `테스트`) 입력 후 Start Attack 클릭 → 값별 Response를 한 번에 비교 가능
